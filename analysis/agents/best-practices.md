# Agent report: best-practices

## Executive summary

Graded against the August-2026 state of the art (verified today against Anthropic's live "Prompting best practices" reference, Agent Skills docs, structured-outputs/caching docs, evals guidance, and the LLM-judge literature), the toolkit splits cleanly: its Epistemics dimension, examples/context techniques, and the two Claude Code skills have aged well — Epistemics almost prefigures Anthropic's current <investigate_before_answering> guidance — while its Process dimension, "fully-specified = 10/10" scoring ideal, role-prompting overclaim, 1-10 single-pass Likert composites, and copy-paste "session intro prompt" delivery read as pre-reasoning-model, pre-context-engineering thinking. The toolkit contains literally zero mentions (verified by grep) of extended/adaptive thinking, context windows, prompt caching, structured outputs, XML tags, subagents, or MCP, and pins no model version for its calibration anchors. The sharpest interviewer attack lines are Anthropic's own current doc ("Prefer general instructions over prescriptive steps... Claude's reasoning frequently exceeds what a human would prescribe"), the context-engineering post's "smallest possible set of high-signal tokens," and the evals-community consensus against 1-10 Likert judges. The honest defenses are real: it is a Description-competency teaching artifact grounded in Anthropic's still-live AI Fluency framework, its anchor mechanism empirically stabilizes scores, and its agent-delegation quality gate anticipates a trend that grew.

## 1. The Aug-2026 state of the art (established with sources)

**1a. Anthropic's living prompting reference.** The docs have consolidated into one "Prompting best practices" page (https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices, fetched 2026-08-12) covering Claude Fable 5, Mythos 5, Opus 5, Opus 4.6–4.8, Sonnet 5. Key doctrines, quoted verbatim from the fetched page:

- Clarity/explicitness: "Claude responds well to clear, explicit instructions... Provide instructions as sequential steps using numbered lists or bullet points **when the order or completeness of steps matters**." (emphasis mine — steps are now conditional, not universal)
- Motivation over decree: "Providing context or motivation behind your instructions... can help Claude better understand your goals." 
- Examples: "Examples are one of the most reliable ways to steer Claude's output format, tone, and structure... Include 3–5 examples for best results," wrapped in `<example>` tags.
- XML structuring: "XML tags help Claude parse complex prompts unambiguously."
- Role: "Setting a role in the system prompt focuses Claude's behavior and tone... Even a single sentence makes a difference." (Behavior and tone — not accuracy.)
- **Thinking models:** "**Prefer general instructions over prescriptive steps.** A prompt like 'think thoroughly' often produces better reasoning than a hand-written step-by-step plan. Claude's reasoning frequently exceeds what a human would prescribe." Manual CoT is now listed only "**as a fallback**" for when thinking is off. On Fable 5/Mythos 5 "thinking is always on"; 4.6+ default to adaptive thinking with an `effort` parameter.
- **Verification is now model-conditional:** "Ask Claude to self-check... **Claude Opus 5 is the exception**: it verifies its own work well without explicit instruction, and verification instructions carried over from prompts tuned for earlier models can cause over-verification... **remove these instructions rather than rewriting them.**"
- **De-escalate emphasis:** "Where you might have said 'CRITICAL: You MUST use this tool when...', you can use more normal prompting"; "Instructions like 'If in doubt, use [tool]' will cause overtriggering."
- Grounding sample prompt `<investigate_before_answering>`: "Never speculate about code you have not opened... give grounded and hallucination-free answers."
- Agentic sections: subagent orchestration is native ("Claude will delegate appropriately without explicit instruction"), multi-context-window state management, memory tools, `<default_to_action>` steering.

**1b. Context engineering.** Anthropic's "Effective context engineering for AI agents" (Sep 2025, https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents — fetch blocked; content verified via multiple search-confirmed secondary sources) reframes the discipline: find "the **smallest possible set of high-signal tokens**"; system prompts should sit at the "**right altitude**" — the Goldilocks zone between "hardcod[ing] complex, brittle logic" and "vague, high-level guidance." Confidence: high on doctrine, medium on verbatim wording.

**1c. Evals-first culture.** Anthropic's prompt-engineering overview (fetched) *begins*: "This guide assumes that you have: 1. A clear definition of the success criteria... 2. Some ways to empirically test against those criteria." The evals doc (https://platform.claude.com/docs/en/test-and-evaluate/develop-tests, fetched) recommends task-specific, automatable, **multidimensional** criteria and *volume* ("Prioritize volume over quality... More questions with slightly lower signal automated grading is better than fewer questions with high-quality human hand-graded evals"), with example judge scales of 1–5 with defined endpoints, plus "use a different model to evaluate than the model used to generate."

**1d. LLM-as-judge consensus.** Hamel Husain/Shreya Shankar's evals FAQ (canonical community reference; hamel.dev blocked, quotes verified via search snippets and the dedicated FAQ page URL https://hamel.dev/blog/posts/evals-faq/why-do-you-recommend-binary-passfail-evaluations-instead-of-1-5-ratings-likert-scales.html): "**Binary evaluations force clearer thinking and more consistent labeling.** Likert scales introduce significant challenges: the difference between adjacent points (like 3 vs 4) is subjective and inconsistent... annotators often default to middle values." 2026 judge guides (comet.com, deepeval.com, futureagi — search-verified) add: one judge per failure mode, split logic into a DAG, validate judges against human labels, inspect judge rationales, mitigate position/verbosity bias.

**1e. Delivery infrastructure.** Agent Skills (beta header `skills-2025-10-02`; docs fetched at https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) are the standard packaging for reusable expertise on claude.ai (custom zip upload), the API, and Claude Code (`.claude/skills/`): "Unlike prompts (conversation-level instructions for one-off tasks), Skills load on demand, so you don't have to repeat the same guidance across conversations." The skill-authoring guide (fetched) mandates conciseness ("Default assumption: Claude is already very smart"), calibrated "degrees of freedom," and "**Create evaluations BEFORE writing extensive documentation**" with a shipping checklist item "At least three evaluations created." Secondary sources (jsmanifest, Medium/Njenga, DataCamp — search-verified, medium confidence) report Claude Code ~2.1.3 merged slash commands into skills, making `.claude/commands/` legacy.

**1f. Platform features an Aug-2026 toolkit is expected to know.** Structured outputs is **GA** ("beta headers are no longer required" — https://platform.claude.com/docs/en/build-with-claude/structured-outputs, fetched). Prompt caching gives cache reads at "0.1× base input token price" and explicitly endorses big reusable rubric/example prompts: "with prompt caching you can get even better performance by including 20+ diverse examples" (https://platform.claude.com/docs/en/build-with-claude/prompt-caching, fetched). ### 2.3 The session-intro-prompt delivery pattern

Verdict: **April-2026-vintage, and arguably dated even then.** Every evaluator says "Copy everything from the horizontal rule below and paste it into a new conversation" and ends with a confirm-back handshake ("Confirm you have understood this framework by summarizing it back to me in two sentences" — prompt-evaluator:187, issue-evaluator:196; codebase-mode:271 has its own variant). Agent Skills — with claude.ai custom upload and Claude Code `.claude/skills/` — had existed for six months when the repo was created (beta header `skills-2025-10-02` in the fetched docs), and their entire premise is that reusable expertise should not be re-pasted per session ("Skills load on demand, so you don't have to repeat the same guidance"). The toolkit even proves it knows this — it ships two SKILL.md files for the issue workflow — but leaves its flagship evaluators as paste-prompts. The confirm-back handshake burns a turn and has no support in current guidance (the fleet's own test harness simply skipped it, analysis/02-empirical-tests.md:92-93). **Honest defense:** paste-prompts are the only genuinely cross-vendor format, and the README's ChatGPT/Gemini compatibility columns (README:100-116) show that portability was a design goal. That defense holds until the interviewer asks why there isn't *also* a skill-packaged version for the Claude-first path the README itself recommends.

### 2.4 0–10 rubric scoring by a single LLM pass

Verdict: **against the 2026 consensus, with one honest mitigation.** The consensus stack: binary pass/fail per failure mode over Likert (Hamel/Shankar: "the difference between adjacent points (like 3 vs 4) is subjective and inconsistent"; ellamind, comet, deepeval concur — search-verified); defined-endpoint 1–5 scales at most (Anthropic evals doc, fetched); judges validated against human labels; scoring math outside the model; structured outputs for machine-consumed results (GA — fetched). The toolkit instead: 1–10 per dimension, single pass, composite average (prompt-evaluator:50-57) or a weighted formula the model must compute itself, `max((Σ w·s)/25, 0.5)` rounded to two decimals (issue-evaluator:95-113), free-form markdown output. The composite gate is structurally compensable: absent Rollback with 10s elsewhere = 210/25 = **8.4 ≥ 7.0**, passing an issue the rubric calls "dangerous" without rollback. **Mitigations that fairness requires reporting:** (1) the fleet's empirical Test B found live sessions never grant the 10s, so all three runs gated correctly at 6.24–6.68 (analysis/02-empirical-tests.md:70-76) — structural defect, not demonstrated live failure; (2) reproducibility of the anchored 1–10 scoring was measured at ±0.25 overall across 5 runs/2 models (analysis/02-empirical-tests.md:22-27) — genuinely better than the Likert-instability literature predicts, and the owner's single best empirical talking point (with the n=5 caveat attached).

### 2.5 Calibration-by-anchors

Verdict: **the mechanism is current; the validation posture is not.** Embedding scored reference examples in a judge prompt is orthodox few-shot judge practice, has real lineage in the cited LLM-Rubric (ACL 2024), and Anthropic's caching doc actively encourages "20+ diverse examples" in reused prompts. What's missing by 2026 standards: (a) the anchors are the *author's own scores of his own prompts* — no second rater, no held-out set, no measured judge-human agreement; (b) no model pinning — "Developed and validated using Claude" (prompt-evaluator:7) names no model or date, and the fleet measured a ~1.3-point systematic downward drift between the April anchor scores and fresh Aug-2026 runs on the same artifact (analysis/02-empirical-tests.md:77-84); (c) nine anchors is a calibration *illustration*, not a calibration *set*, by the volume standards of the evals doc (hundreds of cases). The controlled-degradation methodology for the issue set is, however, a legitimately current technique for building graded references.

## 3. Task 3 — Have reasoning models changed what good prompts look like in ways the framework misses?

**Yes, in four specific, sourceable ways:**

1. **Process over-specification.** The framework's top score requires hand-written ordered steps + checkpoints for *every* prompt (framework:75). Anthropic now says the opposite for thinking models: "Prefer general instructions over prescriptive steps... Claude's reasoning frequently exceeds what a human would prescribe" (fetched living reference). OpenAI's reasoning guidance is blunter still. The framework's own Anchor 7 ironically awards Process 10/10 to a prompt that mostly just asks for a structured report — the scoring narrative and the scoring rule have drifted apart.
2. **"Think first" is becoming a no-op.** Thinking is always-on for the newest generation and adaptive by default for 4.6+; "how to think" is now steered by the `effort` parameter and light reflective nudges ("After receiving tool results, carefully reflect on their quality..."), not by prompt-level CoT commands. The framework's entry-level Epistemics technique is the one part of Epistemics that has expired.
3. **Verification instructions became model-conditional.** "When migrating to Claude Opus 5, remove these instructions rather than rewriting them" (fetched docs) — a sentence that directly collides with a framework whose README calls Epistemics "the single biggest differentiator between a 7/10 and a 10/10 prompt" (README:62) with no model conditioning.
4. **HOW-to-think vs WHAT-to-produce.** Anthropic's current answer: be *very* explicit about the product (output format, action-vs-suggestion, constraints — the docs' `<default_to_action>` and formatting sections) and increasingly *hands-off* about the reasoning process, intervening only to damp overthinking or overeagerness. In PPEP terms: Product and the examples half of Performance appreciated in value; Process depreciated; Epistemics holds for agentic/research work but needs an expiry-aware caveat. The framework has no mechanism — no versioning, no model notes, no conditional scoring — to express any of this.

## 5. Task 5 — Verdict per component, interviewer ammunition, and honest defenses

**PPEP framework — partially dated.** Reads as a thoughtful late-2025 chat-era rubric. *Interviewer cites:* "Prefer general instructions over prescriptive steps" (Anthropic living reference); "smallest possible set of high-signal tokens" (context-engineering post); the persona paper against "most impactful single-line addition." *Defense:* PPEP explicitly covers the **Description competency of the AI Fluency 4D framework** (framework:10), a still-live Anthropic-taught framework (anthropic.skilljar.com, Coursera — verified today); it is a rubric for teaching humans to communicate intent, not an agent-system design doc; its task-type table (framework:177-186) already conditions dimension importance; and Anthropic still endorses steps where order matters. *Weakest point to concede:* the universal Process requirement and the "zero ambiguity = 10/10" ideal need a reasoning-model revision, and the framework has no versioning story.

**Prompt evaluator + calibration set — the mechanism current, the surrounding methodology dated.** *Interviewer cites:* Hamel's binary-vs-Likert FAQ; Anthropic evals doc (multidimensional criteria, volume, different-model grading); no model pinning; author-as-sole-ground-truth. *Defense:* anchored scoring is real technique (LLM-Rubric, ACL 2024); the fleet measured ±0.25 reproducibility across two current models (n=5 — say the caveat before the interviewer does); it's a pedagogical calibration aid, and the anchors double as teaching examples — which pure binary judges cannot do. *Concede:* a 2026 revision would pin models, add a held-out set, and split the composite into per-dimension verdicts.

**Issue evaluator + skills — the best-aged component.** Quality-gating issues before delegating to a coding agent anticipates the 2026 agent-delegation workflow, and the skills' structure (WAIT gates, feedback loop, scoped allowed-tools, <500 lines) matches the current authoring guide. *Interviewer cites:* the 8.4≥7.0 compensation arithmetic; no shipped evals; install path pointing at the legacy commands directory (pending skills-agent confirmation); severity-4 trigger covers vague-Rollback but not absent-Rollback (fleet observation). *Defense:* the fleet's live gate test tripped correctly all 3/3 times because real sessions don't hand out 10s; the fix (hard-fail on absent critical sections) is a two-line change; the rubric's runbook standards themselves (checkboxed AC, exact rollback commands) are timelessly sensible.

**UI/UX evaluators — standards current, tone and tooling slightly dated.** WCAG 2.2 AA is still the operative W3C Recommendation (3.0 is a Mar-2026 Working Draft, final ~2028 — search-verified); Nielsen severity practice is evergreen; grep-driven inventory-before-judgment now mirrors official grounding guidance. Dated bits: "NON-NEGOTIABLE"/"mandatory" emphasis style (current docs: dial it back), and no mention of Playwright-MCP/computer-use runtime verification the docs now recommend.

**README/positioning — reads April-2026.** "Session intro prompt" as a headline concept, versionless model-compat table with ChatGPT/Gemini columns, "confidence: 93%" numerology (methodology agent's lane), and a live-demo section — none of it acknowledges that prompting guidance became model-generation-specific in the year the repo was born.

**The single hardest interview question this audit predicts:** *"Anthropic's own docs now say to prefer general instructions over prescriptive steps and to remove blanket verification instructions on the newest models. Your framework awards its top scores for exactly those two things. How do you version prompting advice?"* The winning answer concedes the drift, points at the Epistemics dimension's convergence with `<investigate_before_answering>` as evidence the instincts were right, cites the ±0.25 reproducibility data, and presents a concrete v2 plan: model-pinned calibration, conditional Process scoring (mirroring the existing Epistemics-N/A logic), per-dimension binary verdicts, structured-output scorecards, and skill-packaged evaluators.
